# 서버 없는 단일 HTML

이슈 [#1](https://github.com/amnotyoung/hwp-diff/issues/1)의 기존 탐색 UI를 단일 HTML로 이식했다. `artifacts/HWP-diff.html` 한 파일을 Windows Edge 또는 Chrome에서 직접 열어 사용한다. 사용자 PC에는 Node.js, EXE, 로컬 HTTP 서버, 인터넷이나 추가 파일이 필요 없다.

## 실행과 빌드

개발 PC에서 의존성을 설치한 후 다음을 실행한다.

```sh
npm ci --ignore-scripts
npm run build:html
```

생성 파일은 `artifacts/HWP-diff.html`이다. `node scripts/build-html.mjs 경로/파일명.html`로 다른 출력 경로도 지정할 수 있다. 생성물과 입력 문서는 Git에 포함하지 않는다. 기존 Node 서버·EXE·DMG 실행 경로도 유지하며, 이 작업에서 EXE·DMG를 새로 만들지는 않았다.

1. HTML 한 파일만 원하는 폴더로 복사하고 Edge 또는 Chrome으로 연다.
2. 구버전과 신버전 HWP 5.x 또는 HWPX를 선택하고 **변경 사항 비교**를 누른다.
3. 내용·서식·메모 탐색과 목록·원본 보기를 독립적으로 전환한다. 검색·필터·선택·세부 구간·스크롤을 유지하며, 유형 전환 자체로 문서 위치를 옮기지 않는다.
4. **저장 (.html)** 또는 **⋯ → 비교 데이터 저장 (.json)**으로 결과를 명시적으로 저장한다. 문서 원본은 수정하지 않는다.

작업 중 **취소**, 미리보기 실패 시 **미리보기 다시 시도**를 제공한다. 비교 실패 후에는 선택 파일을 유지하므로 다시 비교하거나 파일을 교체할 수 있다. 실패·미지원·시간 초과는 ‘변경 없음’ 결과로 만들지 않는다.

## 구현과 지원 범위

- `public/app.js`와 기존 보고서·탐색 상태 모듈을 공용으로 사용한다. 서버 통신은 `public/transport.js`, 단일 HTML은 빌드 시 `browser/transport.js`로 연결한다.
- Kordoc **4.24.21**의 공식 `parse`, `diffBlocks`, `renderDocumentToScene`, 형식 감지 API를 사용한다. 자체 HWP 바이너리 파서를 추가하거나 Kordoc 파서 소스를 수정하지 않았다.
- 작업마다 HTML 안에 포함한 코드를 일반 Blob Worker로 실행한다. 준비 완료 확인 후 파일을 전달하며, 읽기·초기화·파싱·비교·미리보기를 모두 작업 제한 시간에 포함한다. 성공·실패·취소 시 Worker와 Blob URL을 해제한다.
- Buffer, 제한을 적용하는 zlib 호환 계층, 기존 CFB 의존성 연결, JSZip 스트림 지원 엔트리를 포함한다. 파일 시스템·프로세스 실행·암호 해독·PDF/OCR 등 사용하지 않는 Node 기능은 사용할 경우 오류를 낸다.
- HWPX 글자색·글꼴·자간·장평과 메모 비교를 유지한다. HWP의 서식·메모는 미검사로 표시한다. HWP 3.x, HWPML, 암호·DRM·배포용 문서는 HTML 지원 범위에서 제외한다.
- 위치·렌더링 미확인 안내와 기존 Kordoc 미리보기 제한을 유지한다. 설치된 글꼴, 수식, 그림, 배치에 따라 한컴 원본과 다를 수 있다.
- JS·CSS·Worker·샘플·필요 라이브러리와 라이선스 고지는 모두 파일 안에 있다. 외부 폰트나 CDN을 사용하지 않는다. 라이선스 전문은 HTML의 `third-party-notices` template에 포함한다.

## 처리 한도와 저장

| 항목 | 한도/동작 |
| --- | --- |
| 입력 | 파일별 20MiB, 빈 파일 거부 |
| 작업 시간 | 초기화·진행 없는 처리 60초, 완료된 자동 비교 구간이 있을 때만 갱신하며 전체 최대 5분; 취소 시 즉시 종료 |
| HWPX 본문·서식 등 | 내부 항목 500개, 항목당 32MiB·합계 64MiB; 선언 크기와 실제 스트림 크기 확인 |
| HWPX 그림 | BinData의 BMP·PNG·JPEG·GIF·WebP·TIFF가 항목당 64MiB·합계 192MiB를 넘으면 내부 처리본의 그림 바이트만 비워 본문 처리를 계속한다. 파일명·참조·XML·원본은 유지한다. SVG·알 수 없는 첨부 자료는 제외 대상이 아니다 |
| HWP 압축 | 호환 계층에서 스트림당 최대 64MiB 및 Kordoc이 요청한 더 작은 제한 적용; Kordoc 자체 총 압축 해제/구조 제한 유지 |
| 결과 전달 | JSON 인코딩 크기 32MiB 이하 |
| 미리보기 | 기존 전체 텍스트 SVG 64MiB·쪽별 SVG 16MiB 제한 유지 |
| 미리보기 캐시 | 최대 8건 및 직렬화 문자열의 UTF-16 추정치 48MiB 이하 |

브라우저에는 Node Worker의 **512MB 힙 제한이 없다**. 위 수치는 입력·출력·압축·캐시 제한이며 전체 힙 사용량의 상한을 보장하지 않는다. 파서의 중간 자료 구조, 이미지 디코딩, 브라우저 상태 때문에 더 작은 파일도 메모리 부족으로 종료될 수 있다. 자동 처리 범위를 넘어 안전하게 완료할 수 없는 경우 불완전한 결과를 정상 완료로 표시하지 않는다.

문서와 결과는 메모리에서만 유지한다. localStorage, IndexedDB, 서비스 워커, 자동 파일 저장을 사용하지 않는다. 사용자가 내보내기를 누른 결과만 브라우저 다운로드로 저장한다. HTML의 CSP는 네트워크 연결을 차단한다(`connect-src 'none'`); 렌더링 이미지는 data URL로 표시한다.

## 차단 또는 실패 시

보안 해제 옵션과 관리자 권한은 실행 전제가 아니다. 초기 화면의 안내 또는 처리 오류에 따라 다음을 확인한다.

- Edge/Chrome에서 내려받은 HTML 파일 자체를 열었는지 확인한다. 메일·문서 관리 시스템의 미리보기 화면에서는 실행되지 않을 수 있다.
- Worker 시작 실패 시 **다시 시도**를 누른다. 반복되면 기관 담당자에게 로컬 HTML·JavaScript·Blob Worker 실행 정책을 확인한다.
- JavaScript가 실행되지 않아도 정적인 시작 안내를 표시한다. HTML 파일 자체를 기관 정책이 차단하면 앱 내부에서 안내하거나 정책을 진단할 수는 없다.
- 문서 처리 오류는 문서 형식·암호·DRM·손상·용량을 확인한다. 파일 읽기 권한 문제라면 다시 선택한다. 실패 화면에는 결과가 없으며 기존 성공 결과를 새 결과처럼 표시하지 않는다.

## 원격 커밋에 기록된 Windows 검증 — 2026-11-02

Windows 커널 **10.0.26200**, Edge **156.0.4314.58**, Chrome **156.0.8078.79**에서 실제 설치 브라우저를 headless로 실행했다. 브라우저 보안 해제 플래그 없이 Chromium sandbox를 켰다. HTML 한 파일만 새 임시 폴더로 복사해 `file://`로 열고, 네트워크는 오프라인으로 설정했다.

- 브라우저별 8개 사례: HWPX 변경·동일·서식·메모, HWP 압축·비압축·동일, HWP/HWPX 혼합.
- 생성 시각만 제외한 **전체 비교 JSON 일치**, 사례별 양쪽 **전체 미리보기 결과(SVG 포함) 16개 일치**. 같은 렌더러의 Node/브라우저 일치를 뜻하며 한컴 원본과의 완전 일치를 뜻하지 않는다.
- 실제 파일 선택, 비교 취소·재시도, 미리보기 취소·재시도, HTML/JSON 다운로드, 유형/보기 독립성, 검색/필터 복원, 1440px·960px 양쪽 페이지 표시를 검증한다.
- 손상 파일·암호 문서·압축 크기 초과를 실패로 처리하며 정상 결과를 반환하지 않는다. Worker 차단을 주입한 안내와 JavaScript 비활성 상태의 정적 안내를 확인한다.
- 관찰된 HTTP/HTTPS 요청은 **각 브라우저 0건**이다. 로컬호스트 요청도 없었다.
- 단위 테스트에서 20MiB 경계, 압축 메타데이터를 속인 실제 팽창, 항목 수/합계 크기, 압축 중 출력 한도, 초기화/결과 오류·취소/자원 해제 및 60,000ms 중단 타이머를 검증한다. 60초 타이머는 가상 시간으로 검증한다.

HWP 검증 문서는 Kordoc 테스트 구조를 참고한 **합성 HWP 5.x**이다. 실제 업무 HWP, 중첩 표·각주·복잡한 개체의 폭넓은 코퍼스 검증 및 기관 정책이 적용된 사용자 PC의 수동 확인은 남아 있다. 위 Windows 검증을 수행한 원격 커밋 `1ea77c9`에서는 로컬 커밋 `e4696a5`의 macOS 검증 자산을 사용할 수 없어 포함하지 않았다. 이후 로컬 병합에서는 해당 검증 코드와 [검증 기록](browser-html-feasibility.md), Windows EXE 실행 진단 기능을 모두 보존했다.

재현 명령:

```sh
npm test
npm run test:html
# 한 브라우저만 실행할 때:
node scripts/validate-html.mjs msedge
node scripts/validate-html.mjs chrome
```

통합 검증은 설치된 Edge·Chrome을 사용하며 브라우저를 자동 설치하지 않는다. 실행 결과와 화면은 `artifacts/browser-validation/report.json`, `*-1440.png`, `*-960.png`에 저장한다. 입력 문서와 출력 파일은 검증 도구가 만든 합성 자료이며 Git에 포함하지 않는다.


## 로컬 변경 병합 후 검증 — macOS

`1ea77c9`를 로컬 변경과 병합하면서 EXE 실행 진단·출력 가독성 수정·빌드 캐시 설정·기존 HTML 가능성 검증 코드를 보존했다. 단일 HTML은 기존 검증용 JSON 화면과 별개로 전체 비교 UI를 포함한다.

macOS의 설치된 Chrome 156.0.8078.74에서 HTML 한 파일을 임시 폴더로 복사해 오프라인 검증했다. 비교 8종의 전체 JSON, 미리보기 16개, 취소·재시도, HTML/JSON 저장, 유형·보기·검색·필터 상태, 1440px·960px 화면 및 정책 오류 안내가 통과했고 HTTP/HTTPS 요청은 0건이었다. 이는 이번 병합본의 macOS 재검증이며, 위에 기록된 원격 커밋의 Windows 검증과 구분한다. Windows 업무 PC 수동 확인은 사용자 진행 예정이다.

병합 후 `npm test`의 136개 테스트가 모두 통과했다. 일반 `npm test`가 설치 브라우저에 의존하지 않도록 브라우저 통합 검증 스크립트를 `scripts/validate-html.mjs`로 명명했다. 별도 `npm run test:html`은 빌드 후 Edge·Chrome을 검증하며, 한 브라우저만 검증할 때는 `npm run build:html` 후 `node scripts/validate-html.mjs chrome` 또는 `msedge`를 사용한다.


## 압축된 파일 크기와 처리 크기

9MiB HWPX에도 압축을 풀면 수십 MiB가 되는 그림이 들어갈 수 있다. 이전 HTML 버전은 본문과 그림을 합쳐 항목당 32MiB·문서당 64MiB로 검사했기 때문에 비교 전에 거부할 수 있었다. 현재는 본문·서식 한도를 유지하고 래스터 그림을 별도 예산으로 검사한다. Kordoc의 ZIP 전체 사전 검사에는 두 예산의 합인 256MiB를 전달한다. HTML 사전 검사는 선언된 크기와 실제 스트림 크기 양쪽에 별도 한도를 적용하며, HWP 스트림의 64MiB 제한은 바꾸지 않는다.

오류에는 파일명, 원본 크기, 초과한 데이터 종류, 압축 해제 크기 및 적용 한도를 표시한다. 미리보기의 기존 그림 크기 제한은 유지하므로 큰 그림은 생략될 수 있으며 경고를 표시한다. 이는 파일을 다시 저장하거나 원본의 그림을 지우는 기능이 아니다.


수정 검증: 유효한 36MiB BMP 그림 두 개를 포함하고 압축 파일 크기는 약 9MiB인 HWPX 쌍을 생성했다. 기존 32MiB/64MiB 기준을 모두 초과하는 자료에서 본문 수정 1건 검출과 양쪽 미리보기를 확인했다. macOS Chrome 156.0.8078.74의 브라우저 검증은 기존 8종에 이 사례를 추가한 9종·미리보기 18개가 통과했고 외부 요청은 0건이었다. 전체 회귀 테스트는 140개가 통과했다. 이 결과는 생성한 재현 문서 기준이며, 사용자가 보고한 실제 업무 파일 자체를 검증한 것은 아니다.


## 자동 작업 분할

사용자는 원본 두 개만 선택한다. 파일을 별도 문서로 잘라 저장하지 않고, Kordoc 공식 API가 읽은 문단·표를 원자 단위로 유지한 채 내용·서식 대응 계산을 나눈다. 같은 쪽 번호나 일정 개수로 양쪽 문서를 독립 분할하지 않는다.

- 문서 전체의 대응 관계를 유지하며 큰 구간은 250,000개 후보 쌍 정도의 작업으로 순차 계산한다. 점수 행 두 개와 후보당 2비트의 복원 정보만 보관한다. 후보 적격 판정은 Kordoc의 공개 `diffBlocks` API를 사용한다.
- 정확 일치하는 공통 기준점과 분할 계산을 사용하고, 끝난 뒤 이동 검출·문단 번호·항목 ID·변경 집계를 문서 전체 기준으로 만든다. 모든 입력 문단이 결과에 정확히 한 번 포함됐는지 검사하며, 중복·누락 시 결과를 발행하지 않는다.
- 표와 셀 병합·중첩 문단·각주는 절단하지 않는다. 메모·서식은 기존 전체 문서 정보로 검사하므로 분할 경계에서 메모 연결을 새로 만들거나 끊지 않는다.
- 그림 한도 초과 HWPX는 자동으로 그림 바이트가 비어 있는 메모리 처리본을 만든다. 그림 파일명을 제거하면 파서가 그림을 텍스트로 바꿀 수 있으므로 참조와 항목 자체는 유지한다. 본문·표·서식·메모 XML은 바이트 단위로 동일하게 유지하고, 비교 결과와 미리보기에 그림 제외 안내를 표시한다. 사용자 원본은 변경하지 않는다.
- Kordoc이 일부 구역 파싱 실패나 표 잘림을 보고하면 부분 본문으로 비교를 완료하지 않는다. 서식·메모 추출 실패는 기존처럼 미검사로 표시한다.
- 진행률만 반복하는 메시지로 시간을 무한 연장하지 않는다. 완료된 새 구간 번호가 증가할 때만 60초 타이머를 갱신하고, 시작부터 최대 5분을 넘지 않는다.

**범위:** 이는 비교 계산과 큰 그림 처리의 자동 분할이다. Kordoc의 HWP/HWPX 전체 파싱 자체를 스트리밍 파서로 바꾼 것은 아니다. 본문 XML 한 개 32MiB·본문 합계 64MiB, HWP 압축 스트림 제한, 단일 초대형 표·문단 또는 파서 미지원 구조의 한계는 남는다. 이 경우에는 일부를 버려 성공한 것처럼 표시하지 않고 작업을 중단한다. 전체 문서 정확도를 파서 지원 범위 이상으로 보장하지 않는다.

검증: 전체 회귀 149개 통과. 분할 크기를 강제로 작게 한 비교에서 Kordoc 일괄 대응과 동일한 결과를 확인했고, 반복 문장 무작위 150개 사례, 경계 삽입·삭제·표 이동·병합 셀·각주, 그림 경량화 후 서식·메모·XML 보존, 일부 구역 손상 시 중단을 확인했다. macOS Chrome에서는 600개 반복 문단의 수정과 2,101개 문단을 포함한 11종의 전체 비교 JSON·양쪽 미리보기 22개가 Node와 일치했다. 큰 그림 자동 처리, 실제 파일 선택·JSON 저장, 취소·재시도·정책 오류 UI도 통과했으며 HTTP/HTTPS 요청은 0건이었다. 이번 빌드의 Windows 업무 PC 검증은 별도 확인이 필요하다.
